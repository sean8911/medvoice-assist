# Experiments and reproducibility

## Dataset settings

| Stage | Dataset | Input / target | Partition |
| --- | --- | --- | --- |
| Preliminary | Symptom2Disease, 1,200 descriptions, 24 labels | Notebook-specific cleaned symptom text / disease label | Seed-42 960/240 outer split |
| Expanded | [sajjadhadi/disease-diagnosis-dataset](https://huggingface.co/datasets/sajjadhadi/disease-diagnosis-dataset), 493,890 prepared rows, 773 labels overall | `text_cleaned` / `diagnosis` | Supplied 469,195/24,695 split |

The larger dataset is not evidence of independent patients or a controlled
change in diversity alone. The overlap and validation qualifications in
[Results](RESULTS.md) apply to all reproduced comparisons.

Download the relevant dataset and restore or retrain the checkpoints referenced
by each notebook before rerunning. The release supplies the final expanded
773-class BioBERT only, not every preliminary checkpoint. Notebook output is
retained as historical evidence, not proof of a fresh run after cloning.

## Expanded three-model source

Main script:
[train_three_models.py](../TF-IDF%20and%20Fine%20Tune%20BERT/train_three_models.py).
Install its [requirements](../TF-IDF%20and%20Fine%20Tune%20BERT/requirements.txt)
in a separate training environment. Use a CUDA-compatible PyTorch build that
matches the permitted school-server environment when GPU training is intended.
Do not replace the app environment blindly with training dependencies.

The prepared dataset folder must contain:

```text
disease_diagnosis_train_cleaned.csv
disease_diagnosis_test_cleaned.csv
```

Both files require `text_cleaned` and `diagnosis` columns. They are not included
in Git. The loader consumes those prepared files; downloading the raw Hub
parquet files alone does not perform the earlier cleaning or create the expected
CSV schema.

Example new run, executed from `TF-IDF and Fine Tune BERT/`:

```bash
python train_three_models.py \
  --dataset-dir data/disease-diagnosis-dataset \
  --output-dir outputs_new \
  --models tfidf bert biobert \
  --epochs 3 --batch-size 16 --eval-batch-size 32 \
  --max-length 128 --learning-rate 2e-5 --seed 42 --fp16 auto
```

Use a new output directory to avoid replacing retained results. This is a new
training command, not a guarantee of bit-for-bit reproduction of the historical
reports. The old unrelated YOLO `train.sh` is intentionally excluded from the
current GitHub repository. Do not submit it as a medical-classifier job; use the
Python entry point within an appropriately configured permitted job allocation.

## BioBERT continuation source

[train_biobert_and_compare.py](../BioBERT/train_biobert_and_compare.py) trains or
resumes BioBERT and combines it with the two reports in
`BioBERT/baseline_outputs/`. That is why the baseline copies remain in the
curated repository. The final canonical combined reports are in
`3 Models After Training/outputs/`.

The BioBERT script defaults to one epoch and supports checkpoint resumption.
To inspect a proposed run, use `--help`; specify intended epochs and output
directory explicitly. The retained final configuration records three epochs.
Starting from upstream `.bin` weights requires the Torch version checked by the
training script; restoring the inference release uses safetensors instead.

## Speech evaluation source

[evaluate_audio_datasets.py](../voice_biobert_pipeline/evaluation/evaluate_audio_datasets.py)
and [its instructions](../voice_biobert_pipeline/evaluation/README.md) retain the
earlier paired speech/noise pilot. Audio datasets are excluded from Git; source
references are in its `dataset_sources.json`.

Use raw versus enhanced audio from the same recording and noise condition when
comparing WER/CER. Do not describe manual transcript correction as the automatic
ASR result or treat classifier agreement with a reference prediction as accuracy.

No participant feedback, full current-pipeline benchmark or corrected grouped
training run is generated by these documentation updates.
